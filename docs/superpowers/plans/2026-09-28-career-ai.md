# Career AI (Cover Letter · CV · ATS) — Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task. Steps use `- [ ]` syntax.

**Goal:** Add AI assist to the three career tools without replacing what already works:

| Tool | Today (deterministic, keep) | AI adds |
|---|---|---|
| Cover letter | `composeLetter` stitches blocks + placeholders | Generate hook from JD; tailor composed letter to JD |
| CV | `renderCvHtml` from live profile + `cv_layout` | Tailored summary, rewritten bullets, suggested block order — stored as per-item overrides |
| ATS | `evaluateAts` frequency keywords, 0–100 score | Real requirement extraction, synonym-aware matching, gap → "add X to section Y" suggestions |

**Rule:** AI output is always a *proposal* the user accepts. Profile data is never overwritten. Deterministic score stays the source of truth.

**Architecture in one line:** one Supabase Edge Function `career-ai` calls any OpenAI-compatible `/chat/completions` endpoint with JSON mode; the provider is 3 env vars, so switching DeepSeek ↔ Qwen ↔ Gemini is a config change, not a code change.

**No new npm dependencies.** Plain `fetch` in the function; `zod` (already in `@himan/shared`) validates responses client-side.

## 1. Model research (Sept 2026)

Prices per 1M tokens. All are OpenAI-API-compatible and support JSON output.

| Provider / model | Input | Output | Free tier | Notes |
|---|---|---|---|---|
| **DeepSeek `deepseek-flash`** | $0.15 (off-peak) – $0.30 (peak); cache hit ~$0.003–0.006 | $0.60 – $1.20 | No (≈$2 top-up lasts months) | 1M context, JSON mode, base `https://api.deepseek.com`. **Servers in China** |
| DeepSeek `deepseek-v4-pro` | $0.66 – $1.32 | $1.98 – $3.96 | No | Overkill here |
| **Qwen3.8 Flash** (Alibaba, Singapore endpoint) | $0.14 | $0.42 | 1M tokens/model for 90 days | Cheapest paid option; data stays in Singapore region |
| Qwen3.7 Plus | $0.40 | $1.60 | same | Better writing quality |
| Gemini 2.5 Flash-Lite | $0.10 | $0.40 | Yes: ~5–15 RPM, ~1,000 req/day | **Free tier may use your data for training** — bad fit for CV PII |
| OpenRouter `:free` models | $0 | $0 | 50 req/day (1,000/day after $10 credit) | Model list changes constantly; unreliable for a product |

**Cost per call (worst case, peak DeepSeek Flash):** tailor CV ≈ 5k in + 1.5k out ≈ **$0.0033**. 100 job applications × 3 AI calls ≈ **$1**.

**Recommendation:**
**Chosen (2026-09-28): Gemini free tier** — `$0`, no card.
- Base URL (OpenAI-compatible): `https://generativelanguage.googleapis.com/v1beta/openai`
- Model: `gemini-2.5-flash-lite` (highest free quota, ~1,000 req/day, 5–15 RPM). Swap to `gemini-2.5-flash` if writing quality is weak.
- **Trade-off accepted:** free-tier prompts may be used by Google for training. Mitigated by decision #4 (name, phone, email, links, location never sent).
- **Rate limits:** free RPM is low → client must handle `429` from Google (surface "AI busy, retry in a minute") separately from our own daily cap.

Upgrade path if free tier bites: DeepSeek `deepseek-flash` (best quality/price) or Qwen3.8 Flash Singapore (data residency). Same code, different secrets.

Because the function reads `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL`, all four are one `supabase secrets set` away.

Sources: [DeepSeek pricing](https://api-docs.deepseek.com/quick_start/pricing), [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [Qwen pricing (BenchLM)](https://benchlm.ai/alibaba/api-pricing), [OpenRouter rate limits](https://openrouter.zendesk.com/hc/en-us/articles/39501163636379-OpenRouter-Rate-Limits-What-You-Need-to-Know).

## 2. Key decisions

1. **API key never touches the browser.** Edge Function holds it as a secret; `verify_jwt = true` so only signed-in (allowlisted) users can call it.
2. **One function, three tasks** (`task: 'letter_hook' | 'tailor_letter' | 'tailor_cv' | 'ats_analyze'`). One deploy, one rate limiter, one prompt file.
3. **Rate limit in Postgres:** `ai_usage(user_id, day, count)` + `increment_ai_usage()` RPC; function rejects above `AI_DAILY_LIMIT` (default 50). Input caps: JD ≤ 15k chars, CV text ≤ 20k chars.
4. **Minimise PII sent.** Strip `phone`, `email`, `links`, `location` before sending. Name not needed for any task — omit it.
5. **Hallucination guard (pure, testable):** `unsupportedClaims(output, sourceText)` flags numbers/percentages/company names in AI output that don't appear in the input. UI shows them as warnings before Accept.
6. **Validation lives in `@himan/shared/career`** (zod schemas). Function passes model JSON through; client parses → on failure shows "AI returned an unexpected format, try again".
7. **One job description per editor session.** JD currently lives inside `AtsPanel` local state. Lift it to `ItemEditorPage` so letter, CV and ATS all use the same pasted JD.
8. **Prompt caching for free:** put the long, stable part (system prompt + JD) first in messages, variable part last — DeepSeek/Qwen automatic prefix caching cuts repeat-JD input cost ~50×.

### Phase 1 — Backend (≈2 h)

- [ ] **1.1 Migration** `supabase/migrations/20260928000100_ai_usage.sql`
  ```sql
  CREATE TABLE public.ai_usage (
    user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    day     date NOT NULL DEFAULT current_date,
    count   int  NOT NULL DEFAULT 0,
    PRIMARY KEY (user_id, day)
  );
  ALTER TABLE public.ai_usage ENABLE ROW LEVEL SECURITY;
  CREATE POLICY "own usage readable" ON public.ai_usage FOR SELECT USING (auth.uid() = user_id);

  CREATE FUNCTION public.increment_ai_usage() RETURNS int
  LANGUAGE sql SECURITY DEFINER SET search_path = public AS $$
    INSERT INTO ai_usage (user_id, day, count) VALUES (auth.uid(), current_date, 1)
    ON CONFLICT (user_id, day) DO UPDATE SET count = ai_usage.count + 1
    RETURNING count;
  $$;
  REVOKE ALL ON FUNCTION public.increment_ai_usage() FROM PUBLIC;
  GRANT EXECUTE ON FUNCTION public.increment_ai_usage() TO authenticated;

  ALTER TABLE public.career_items ADD COLUMN cv_overrides jsonb;  -- see Phase 3
  ```
- [ ] **1.2 Edge Function** `supabase/functions/career-ai/index.ts` (Deno, ~120 lines):
  ```ts
  // 1. CORS preflight
  // 2. Create supabase client with the caller's Authorization header → rpc('increment_ai_usage')
  //    count > AI_DAILY_LIMIT → 429 { error: 'daily_limit' }
  // 3. Parse { task, input }; reject unknown task / oversize input → 400
  // 4. const { system, user } = PROMPTS[task](input)
  // 5. fetch(`${AI_BASE_URL}/chat/completions`, {
  //      model: AI_MODEL, temperature: 0.4,
  //      response_format: { type: 'json_object' },
  //      messages: [{ role:'system', content: system }, { role:'user', content: user }] })
  //    timeout 45s via AbortSignal.timeout
  //    upstream 429 (Gemini free RPM) → return 503 { error: 'provider_busy' }
  // 6. return JSON.parse(choices[0].message.content)  (502 on parse fail)
  ```
  `supabase/config.toml`: `[functions.career-ai] verify_jwt = true`.
- [ ] **1.3 Prompts** `supabase/functions/career-ai/prompts.ts` — one function per task returning `{system, user}`. Shared system rules:
  - "Use only facts present in PROFILE/CV/BLOCKS. Never invent employers, dates, numbers, tools."
  - "Match the job description's vocabulary where the candidate genuinely has the skill."
  - "Return JSON matching this shape: …" (shape inlined per task).
  - Plain, confident, no clichés ("passionate", "dynamic", "synergy"); no em-dash chains.
- [ ] **1.4 Deploy** `supabase functions deploy career-ai`; smoke test with `curl` + user JWT.

- [ ] **4.2 Cover letter**

  - "✨ Tailor to job" in letter preview → `tailor_letter` (input: composed `text`, JD, company, jobTitle) → side-by-side dialog: current vs proposed, `changes[]` list, `unsupportedClaims` warnings, **Accept / Discard**.

- [ ] **4.3 CV**
